# Запись на приём — Уймин Антон Григорьевич

Сервис бронирования места в очереди на приём к преподавателю. Студент выбирает
свободный слот (по умолчанию 5 минут), указывает ФИО и группу, проходит короткое
задание по сетевому и системному администрированию вместо скучной капчи — и
получает талон со ссылкой на отмену.

Оформление, шрифты и логотип повторяют сайт научного журнала
«Профессионалитет» (`uralolimp.website`): та же палитра, та же типографика,
светлая и тёмная темы.

---

## Быстрый старт

```bash
cp .env.example .env
sed -i "s/CHANGE_ME_SECRET/$(openssl rand -hex 32)/" .env
sed -i "s/CHANGE_ME_DB_PASSWORD/$(openssl rand -base64 18 | tr -d '/+=')/" .env
# ADMIN_PASSWORD впишите руками

docker compose up -d --build
```

Сервис поднимется на `127.0.0.1:8080` — ровно так, как нужно для публикации
через ваш внешний nginx.

| Адрес | Что там |
|---|---|
| `/` | расписание дней приёма |
| `/d/2026-09-23` | сетка времени на день |
| `/admin` | панель преподавателя |
| `/healthz` | проверка живости для мониторинга |

### Проксирование через существующий nginx

```nginx
server {
    server_name queue.uralolimp.website;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Дальше обычный `certbot --nginx -d queue.uralolimp.website`.

## Как этим пользоваться

### Преподаватель

1. `/admin` → логин и пароль из `.env`.
2. **Дни и окна** → создать день: дата, кабинет, окно `14:00–16:00`, 5 минут на
   приём. Окно сразу нарезается на слоты.
3. В дне можно добавить второе окно (например, до пары и после), закрыть
   отдельные слоты кнопкой «Закрыть» — на обед или на техническую паузу.
4. Снятый флажок «Опубликован» прячет день от студентов: удобно готовить
   расписание заранее.
5. Во время приёма — отметки **Принят / Неявка / Ожидает** прямо в таблице дня
   или в сводке.
6. **Печать списка**, **выгрузка XLSX** и **CSV** — на странице дня. В печатной
   форме есть колонки «Отметка» и «Подпись».
7. **Цели визита** — свой справочник: что именно студент выбирает в форме.
   Любой пункт можно пометить как требующий комментария.

### Студент

Выбирает день → свободный слот → ФИО, группу, цель визита → решает задание →
получает талон. Ссылка на талон запоминается в браузере и показывается на
главной в блоке «Ваша запись». Отмена — там же, одной кнопкой.

## Правила записи

Заданы в `.env`, меняются без пересборки образа (нужен только
`docker compose up -d`):

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `MAX_ACTIVE_BOOKINGS` | активных броней на студента | `1` |
| `BOOKING_LEAD_MINUTES` | за сколько минут до слота закрывается запись | `5` |
| `DAYS_AHEAD` | горизонт показа расписания, дней | `30` |
| `GROUP_PATTERN` | формат номера группы | `^[А-ЯЁ]{2}-[0-9]{2}-[0-9]{2}$` |
| `GROUP_PLACEHOLDER` | пример в подсказке | `КТ-24-04` |
| `CAPTCHA_TTL_SECONDS` | сколько живёт задание капчи | `600` |
| `CAPTCHA_MAX_ATTEMPTS` | попыток, потом выдаётся новое задание | `4` |

Студент — это пара «ФИО + группа». ФИО сравнивается без учёта регистра,
лишних пробелов и разницы `е`/`ё`, так что «иванов иван иванович» не обойдёт
лимит броней.

## Капча

Четыре типа, выбираются случайно. Все работают одним пальцем на телефоне:
никакого перетаскивания и мелких целей, минимальная кнопка — 52 px.

| Тип | Что делает студент | Чему учит |
|---|---|---|
| **Правда или миф** | три карточки, две большие кнопки | развенчивает мифы: RAID ≠ бэкап, VPN ≠ анонимность, 5 ГГц ≠ дальнобойность |
| **Один верный ответ** | тап по одному из четырёх вариантов | ALT Linux, Eltex, EcoRouter, CyberBackup, порты и утилиты |
| **Где искать причину** | тап по узлу схемы сети | диагностика: APIPA, DNS, канал провайдера, петля в коммутаторе |
| **Выберите маску** | ползунок `/24…/30` с живым пересчётом хостов | адресация и размер подсети |

Правильный ответ **никогда не уходит в браузер**: в HTML попадает только то,
что нужно нарисовать. Проверка, счётчик попыток и «погашение» задания при
отправке формы — на сервере. Одно решённое задание = одна бронь.

Неверный ответ всегда разбирается по существу — в этом и смысл:

> «RAID спасает от смерти диска, но не от „ой, я удалил папку“ и не от
> шифровальщика: удаление зеркалируется на второй диск мгновенно.»

Посмотреть и прогнать все типы: **`/admin/captcha`**.

### Как добавить свой вопрос

Всё лежит в `app/captcha/bank.py`:

```python
TRUTH_MYTH = [
    ("Утверждение", True, "Почему именно так"),
]
QUIZ = [
    ("Вопрос?", ["верный", "мимо", "мимо", "смешной"], 0, "Разбор"),
]
SCHEME_CASES = [
    ("Симптом", "rt", "Почему это маршрутизатор"),
]
SUBNET_CASES = [(20, "лаборатория на двадцать машин")]
```

Добавили строку — `docker compose restart app`, и вопрос в ротации. Варианты в
квизе перемешиваются при каждой выдаче, так что «всегда первый» не сработает.

## Устройство

```
docker-compose.yml     app (FastAPI) + db (PostgreSQL 16)
app/
├── main.py            сборка приложения, создание таблиц, начальные данные
├── config.py          все настройки из переменных окружения
├── models.py          ORM-модели и защита от двойной брони
├── security.py        сессии, токены отмены, нормализация ФИО и группы
├── templating.py      общий Jinja: фильтры дат, статусы
├── captcha/           банк заданий и серверная проверка
├── routers/           public.py — студенты, admin.py — преподаватель
├── services/          slots.py — расписание, export.py — XLSX и CSV
├── templates/         страницы (Jinja2, серверный рендер)
└── static/            css, js, шрифты и логотип — всё локально, без CDN
```

**Стек:** Python 3.12, FastAPI, Jinja2 (серверный рендер), SQLAlchemy 2.0,
PostgreSQL 16. JavaScript — один файл на 250 строк, без сборки и фреймворков.
Шрифты и логотип лежат рядом: сервис полностью работает в локальной сети без
доступа в интернет.

### Почему два студента не займут один слот

На таблице броней стоит частичный уникальный индекс:

```sql
CREATE UNIQUE INDEX uq_booking_active_slot
    ON booking (slot_id) WHERE status <> 'cancelled';
```

Проверка «слот свободен» в коде — это удобство для интерфейса; настоящая
гарантия даётся базой. Если два человека нажали кнопку одновременно, второй
получит честное «этот слот заняли за секунду до вас» вместо двух записей на
одно время.

При изменении окна слоты, на которые уже кто-то записан, не пересобираются —
студенту не поменяют время задним числом.

## Данные

История хранится бессрочно: выгрузки за прошлые семестры остаются доступны.
Удаление — только вручную, кнопкой в разделе «Записи».

В сетке времени другие студенты видят только «Занято» — ни ФИО, ни группы.
Полные данные видит преподаватель в админке.

Бэкап базы:

```bash
docker compose exec -T db pg_dump -U au_queue au_queue | gzip > priem-$(date +%F).sql.gz
```

Восстановление:

```bash
gunzip -c priem-2026-09-18.sql.gz | docker compose exec -T db psql -U au_queue au_queue
```

По правилу 3-2-1, о котором спрашивает капча: положите копию не на тот же диск.

## Обслуживание

```bash
docker compose logs -f app        # что происходит
docker compose restart app        # после правки банка вопросов
docker compose up -d --build      # после правки кода
docker compose down               # остановить (данные в volume остаются)
docker compose down -v            # остановить и стереть базу
```

Смена пароля администратора: правите `ADMIN_PASSWORD` в `.env`, затем
`docker compose up -d`. Выданные сессии живут 12 часов.

### Самопроверка

```bash
./scripts/smoke.sh
```

47 проверок на живом стеке: вход в админку, нарезка окна на слоты, все четыре
типа капчи, бронь, лимит броней, приватность сетки, выгрузки XLSX и CSV,
статусы, отмена и защита от двойной брони на уровне базы. Скрипт создаёт
тестовый день на послезавтра и подчищает его за собой. Логин и пароль берутся
из `.env` — если поменяли, поправьте их в начале скрипта.
