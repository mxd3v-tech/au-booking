# Живая очередь на приём — #au_team

Студент сканирует QR-код у кабинета, вводит фамилию, имя и группу, решает
короткое задание по сетевому и системному администрированию вместо скучной капчи — и
попадает в список. Список открытый: видно, кто за кем стоит и сколько человек
впереди. Преподаватель отмечает «принят» или «не подошёл» и в конце закрывает
приём — список уходит в историю.

Записи на конкретное время нет: очередь живая, номера выдаются по порядку
прихода.

Оформление, шрифты и логотип повторяют сайт научного журнала
«Профессионалитет» (`uralolimp.website`): та же палитра, та же типографика,
светлая и тёмная темы.

## Быстрый старт

```bash
cp .env.example .env
sed -i "s/CHANGE_ME_SECRET/$(openssl rand -hex 32)/" .env
sed -i "s/CHANGE_ME_DB_PASSWORD/$(openssl rand -base64 18 | tr -d '/+=')/" .env
# ADMIN_PASSWORD впишите руками

docker compose up -d --build
```

**Обязательно заполните `ORG_NAME`, `ORG_ADDRESS` и `PRIVACY_CONTACT`** —
это оператор персональных данных в тексте согласия. Без `ORG_NAME` сервис
работает, но при старте пишет в журнал предупреждение, а на странице
`/privacy` висит «оператор не указан»: согласие без оператора юридической
силы не имеет. См. «Персональные данные».

| Адрес | Что там |
|---|---|
| `/` | очередь: список, свой номер, кнопка «встать» |
| `/q` | то же самое, короткий адрес для QR-кода |
| `/admin` | панель приёма: открыть, отмечать, закрыть |
| `/admin/qr` | QR-код на дверь, готовый к печати |
| `/privacy` | обработка персональных данных и текст согласия |
| `/healthz` | проверка живости для мониторинга |

По умолчанию сервис слушает `0.0.0.0:8080` — адрес и порт задаются
`BIND_ADDR`/`BIND_PORT` в `.env`. Если он должен быть доступен только через
внешний nginx, поставьте `BIND_ADDR=127.0.0.1` или закройте порт на файрволе.

### Проксирование через существующий nginx

Готовые конфиги лежат в `deploy/nginx/`, оба проверены `nginx -t`:

| Файл | Когда брать |
|---|---|
| `queue.uralolimp.website.conf` | свой поддомен и HTTPS — основной вариант |
| `queue-lan.conf` | локальная сеть без домена, студенты заходят по IP |

```bash
sudo cp deploy/nginx/queue.uralolimp.website.conf /etc/nginx/conf.d/
sudo sed -i 's/queue.uralolimp.website/ваш.домен/g' /etc/nginx/conf.d/queue.uralolimp.website.conf
sudo certbot --nginx -d ваш.домен
sudo nginx -t && sudo systemctl reload nginx
```

**После включения HTTPS поставьте `COOKIE_SECURE=1` в `.env`** и выполните
`docker compose up -d` — тогда куки сессии и записи не уйдут по открытому http.
Для LAN-варианта флаг должен остаться нулём, иначе вход в админку перестанет
работать.

Что в конфиге сверх голого `proxy_pass`:

- **X-Forwarded-For** — без него приложение видит все записи как пришедшие
  с `127.0.0.1`, и защита от флуда теряет смысл;
- **кэш статики** — шрифты и логотип на 30 дней, CSS и JS на час. Внутри
  `location` намеренно нет ни одного `add_header`: как только он там появляется,
  nginx перестаёт наследовать заголовки безопасности с уровня `server`,
  и статика остаётся без `nosniff`;
- **CSP без `unsafe-inline` для скриптов** — инлайновых `<script>` и `onclick`
  в шаблонах нет, тема подключается файлом `/static/js/theme.js`;
- **отдельная зона лимита для `/api/queue`** — страница очереди опрашивает этот
  адрес раз в 15 секунд у каждого открытого телефона. Группа из 25 человек за
  одним NAT даёт под сотню запросов в минуту просто потому, что все смотрят на
  свой номер; общий лимит форм отрезал бы это честное поведение первым делом;
- **лимиты на формы** — аккуратные: 120 запросов в минуту с запасом `burst=40`.
  Подбор пароля в `/admin/login` отрезан жёстче, там же есть закомментированный
  `allow` по сети колледжа;
- `/healthz` наружу закрыт.

## Как этим пользоваться

### Преподаватель

1. `/admin` → логин и пароль из `.env`.
2. **Открыть приём**: кабинет (по умолчанию 1215), время «с» и «до»
   (подставляются текущие два часа, поправьте под себя) и заметка вроде
   «сегодня только пересдачи». Всё это студенты видят в шапке. Формат везде
   24-часовой — «09:00», «14:30», «18:00». Время «до» — это конец записи,
   см. ниже. Оставите поле пустым — приём закроется только кнопкой.
3. Пока приём открыт, любой, кто отсканирует QR, встаёт в конец очереди.
4. Напротив каждого — **Принят** и **Не подошёл**. Отметили не того — кнопка
   «Вернуть в очередь» на месте. **Убрать** удаляет запись совсем.
5. Пришедшего без телефона можно вписать вручную — форма под таблицей. Если
   в очереди уже есть такие же фамилия и имя, но пришёл другой студент —
   отметьте «это однофамилец», иначе запись не пройдёт. Галочка «согласие на
   обработку данных получено» обязательна: спросите человека вслух или
   возьмите бумажное согласие. Через эту же форму проходят те, кому отказала
   студенческая: настоящая фамилия, похожая на запрещённое слово, и студенты
   младше 18 лет — за них согласие даёт законный представитель.
6. **Закрыть приём**: список уходит в историю, следующий приём начнётся с №1.
   Обычно нажимать не приходится — см. «Когда приём заканчивается».
7. **Печать**, **XLSX** и **CSV** — на странице приёма и в истории. В печатной
   форме есть колонки «Отметка» и «Подпись».
8. **QR-код** — `/admin/qr`, лист сразу готов к печати. Код постоянный,
   перепечатывать его к каждому приёму не нужно.
9. **Цели визита** — свой справочник: что именно студент выбирает в форме.
   Любой пункт можно пометить как требующий комментария.

### Студент

Сканирует код → видит очередь → «Встать в очередь» → фамилия и имя, группа,
цель визита, задание про сети, согласие на обработку данных → получает номер. Дальше страница сама
обновляется и показывает, сколько человек впереди. Передумал — «Выйти из
очереди».

## Правила

| Что | Как |
|---|---|
| Одна запись на человека | Одна на весь приём — и пока ждёт, и после отметки «Принят». Дважды встать нельзя ни с другого телефона, ни почистив куки, ни сменив группу |
| Однофамильцы | Второе такое же ФИО заводится только вручную из админки, галочкой «это однофамилец» |
| Фамилия из двух слов | Принимается как есть: «Абдул Гамид Рашид», «Ван Дейк Иван», «Салтыков-Щедрин Иван» — до четырёх слов |
| Отчество | Не нужно, и форма его не примет. Им дописывались «новые» люди, чтобы встать в очередь второй раз |
| Мат в ФИО | Форма не примет: слово сверяется с корнями брани, с поправкой на латиницу вместо кириллицы, цифры вместо букв и разбивку на слоги |
| Согласие на ПДн | Без отметки запись не проходит. У записи хранится редакция текста и время — см. «Персональные данные» |
| Вернуть в очередь | Может только преподаватель: сменить статус записи обратно на «Ожидает» или удалить её |
| Видимость | Фамилию, имя, группу и номер видят все в очереди. Цель визита и комментарий — только админка |
| Выход из очереди | В любой момент, место освобождается. Записаться заново в этот же приём уже нельзя — только через преподавателя |
| Конец записи | По времени «до»: новых не записывают, уже стоящих дообслуживают, дальше приём закрывается сам |
| История | Хранится `RETENTION_DAYS` дней после закрытия приёма, дальше удаляется сама. Раньше срока — вручную, кнопкой |

Настройки в `.env`, меняются без пересборки образа (нужен только
`docker compose up -d`):

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `ROOM` | кабинет, подставляемый при открытии приёма | `1215` |
| `POLL_SECONDS` | как часто страница подтягивает свежий список | `15` |
| `PUBLIC_URL` | внешний адрес для QR-кода | из запроса |
| `TZ` | часовой пояс | `Europe/Moscow` |
| `GROUP_PATTERN` | формат номера группы | `^[А-ЯЁ]{2}-[0-9]{2}-[0-9]{2}$` |
| `GROUP_PLACEHOLDER` | пример в подсказке | `КТ-24-04` |
| `CAPTCHA_TTL_SECONDS` | сколько живёт задание капчи | `600` |
| `ORG_NAME` | оператор персональных данных — название учебного заведения | пусто |
| `ORG_ADDRESS` | его адрес на странице `/privacy` | пусто |
| `PRIVACY_CONTACT` | куда писать про свои данные и отзыв согласия | пусто |
| `CONSENT_VERSION` | редакция текста согласия, хранится в каждой записи | `1` |
| `RETENTION_DAYS` | сколько дней живёт закрытый приём; `0` — не удалять | `180` |
| `BANNED_NAMES_EXTRA` | свои запрещённые в ФИО слова, через запятую | пусто |

Для стандартного `GROUP_PATTERN` форма автоматически расставляет дефисы.
Если задать другой формат, например три буквы в группе, включается свободный
ввод без обрезания символов; соответствие формату проверяет сервер.

Фамилия сравнивается без учёта регистра, лишних пробелов, разницы `е`/`ё` и
порядка слов, так что «иванов иван» не обойдёт запрет на второй номерок.
Дописать к ФИО лишнее слово тоже не выйдет: сравниваются наборы слов, и
«Абдул Гамид Рашид» с «Абдул Рашид» — это один человек.

## Когда приём заканчивается

Время «до» — не подпись, а настоящая граница записи. Живую очередь при этом
никто не обрывает на полуслове:

| Момент | Что происходит |
|---|---|
| наступило время «до» | **запись закрывается**: новые номерки не выдаются, `/join` уводит на страницу очереди, а прямой POST по заранее открытой форме не проходит |
| после времени «до» | те, кто успел встать, остаются с номерками — преподаватель спокойно их дообслуживает |
| последнего отметили | приём **закрывается сам** и уходит в историю |
| нужно ещё поработать | поставьте в «Параметрах приёма» время «до» побольше — запись снова откроется |

Студент видит честную шапку: «Запись закрыта · 14:00–16:00 · принимают тех,
кто успел», и страница сама это заметит — обновлять не нужно. Преподаватель
видит в панели, сколько человек осталось дообслужить.

Отдельного планировщика в сервисе нет: состояние пересчитывается при каждом
чтении очереди — страницу и так открывают и студенты, и преподаватель.
Решение «закрыть» принимается под той же блокировкой, что и запись, поэтому
приём не может закрыться ровно между проверкой и постановкой в очередь.

Приём, открытый без времени «до», по часам не заканчивается вовсе: его
закрывает только кнопка. Приём через полночь («с 23:50 до 00:30») считается
правильно — конец берётся от даты открытия.

## Капча

Восемь типов, выбираются случайно. Все работают одним пальцем на телефоне:
никакого перетаскивания и мелких целей, минимальная кнопка — 52 px.

| Тип | В банке | Что делает студент | Чему учит |
|---|---|---|---|
| **Правда или миф** | 44 утверждения, по три в задании | три карточки, две большие кнопки | развенчивает мифы: RAID ≠ бэкап, VPN ≠ анонимность, скрытый SSID ≠ защита |
| **Один верный ответ** | 33 вопроса | тап по одному из четырёх вариантов | ALT Linux, Eltex, EcoRouter, CyberBackup, адресация, порты и утилиты |
| **Где искать причину** | 12 сценариев | тап по узлу схемы сети | диагностика: APIPA, DNS, канал провайдера, петля в коммутаторе |
| **Выберите маску** | 21 задача × 8 сетей | ползунок `/24…/30` с живым пересчётом хостов | адресация и размер подсети |
| **Сервис ищет порт** | 22 сервиса, по три в задании | три списка: какому сервису какой порт | стандартные порты: SSH, DNS, RDP, SMB, LDAP, SNMP, СУБД |
| **Что за чем** | 13 цепочек | тапы по этапам в нужном порядке | DORA, рукопожатие TCP, восстановление копий, загрузка Linux, выпуск TLS |
| **Права без 777** | 14 задач | тап по нужному `chmod` | 640, 600 для ключа SSH, 750 для скрипта, sticky bit и SGID |
| **Читаем журнал** | 15 фрагментов | строка лога и четыре объяснения | `Address already in use`, NXDOMAIN, OOM killer, `Connection refused` |

Правильный ответ **никогда не уходит в браузер**: в HTML попадает только то,
что нужно нарисовать. Проверка и «погашение» задания при отправке формы — на
сервере. Одно решённое задание = один номерок. Погашение атомарное: два
параллельных запроса не могут использовать одно задание.

Попытка одна. Неверный ответ сжигает задание — повторно оно не принимается
даже прямым запросом, а на экране сразу появляется задание **другого типа**:
сервер присылает его тем же ответом, вместе с разбором ошибки. Кнопка
«Другое задание» тоже меняет тип, а не перетасовывает тот же самый.

Неверный ответ всегда разбирается по существу — в этом и смысл:

> «RAID спасает от смерти диска, но не от „ой, я удалил папку“ и не от
> шифровальщика: удаление зеркалируется на второй диск мгновенно.»

Посмотреть и прогнать все типы: **`/admin/captcha`**.

### Как добавить свой вопрос

Всё лежит в `app/captcha/bank.py`:

```python
TRUTH_MYTH = [
    ("Утверждение", True, "Почему именно так"),
]
QUIZ = [
    ("Вопрос?", ["верный", "мимо", "мимо", "смешной"], 0, "Разбор"),
]
SCHEME_CASES = [
    ("Симптом", "rt", "Почему это маршрутизатор"),
]
SUBNET_CASES = [(20, "лаборатория на двадцать машин")]
PORT_SERVICES = [("SSH", 22)]
ORDER_CASES = [
    ("Условие", ["первый этап", "второй", "третий"], "Почему такой порядок"),
]
PERMISSION_CASES = [
    ("Что нужно разрешить?", ["640", "644", "600", "750"], 0, "r = 4, w = 2, x = 1"),
]
LOG_CASES = [
    ("строка журнала", "Вопрос?", ["верный", "мимо", "мимо", "мимо"], 0, "Разбор"),
]
```

`PERMISSION_CASES`, `LOG_CASES` и `QUIZ` хранят верный вариант первым — индекс
указывает на него до перемешивания. `ORDER_CASES` хранит этапы в правильном
порядке, на экран они выходят перетасованными.

Добавили строку — `docker compose restart app`, и вопрос в ротации. Варианты в
квизе перемешиваются при каждой выдаче, так что «всегда первый» не сработает.

## ФИО: двойные фамилии и фильтр брани

Очередь висит на экране у кабинета, и фамилия из неё видна всем, кто стоит
рядом. Поэтому ФИО проверяется дважды: на формат — в `security.py`, на
содержание — в `moderation.py`.

**Формат.** Фамилия и имя — от двух до четырёх слов, буквы, пробел, дефис и
апостроф. «Салтыков-Щедрин Иван», «Абдул Гамид Рашид», «Ван Дейк Иван» и
«Д'Артаньян Шарль» проходят. Отчество — нет: им дописывали «новых» людей,
чтобы записаться второй раз. Отчество узнаётся по окончанию (`-ович`,
`-евна`, `-ична` и родственным) и только начиная с третьего слова — иначе под
запрет ушли бы «Петрович Марко» и «Ильич Владимир», где это фамилия.

Дописать слово и получить второй номерок всё равно не выйдет: очередь
сравнивает не строки, а наборы слов. Если набор нового ФИО вложен в уже
записанный или наоборот — это тот же человек, и он получает отказ с
объяснением. Проверка идёт под той же блокировкой приёма, что и выдача номера,
поэтому проехать мимо неё на гонке запросов нельзя.

**Содержание.** Слово «складывается» — приводится к тому, что читает глаз:
похожие на буквы латиница и цифры становятся кириллицей (`Xyeв` → `хуев`),
регистр и `ё` снимаются, повторы букв сжимаются (`хуууй` → `хуй`), всё, кроме
букв, выбрасывается. Затем сложенное слово сверяется с корнями брани. Кроме
отдельных слов проверяется и ФИО целиком, без пробелов: брань любят разбивать
на слоги («Ху Йов»). Отдельным списком идут транслит и английские слова —
сложенное в кириллицу `fuck` превратилось бы в безобидный мусор.

Корни намеренно узкие, а на настоящие фамилии, которые в них попадают, стоят
исключения: «Херсонский», «Херасков», «Мудрецов», «Сукачёв», «Мандельштам»,
«Лебедев», «Объедков», «Требухов». Ложное срабатывание обиднее пропуска —
человеку отказывают в его собственной фамилии. Заодно отсекается бессмыслица
вида «Ааа Ббб»: в каждом слове должна быть гласная.

Список — защита от шуток, а не цензура, и ошибиться он всё-таки может.
Поэтому **в админке фильтра нет**: настоящую фамилию, попавшую под него,
преподаватель вписывает вручную — решает живой человек, который видит
студента. Свои слова добавляются в `BANNED_NAMES_EXTRA` через запятую и
проверяются по той же нормализации. Сработавший корень уходит в журнал
(`docker compose logs app`), само ФИО — нет.

### Что гарантирует база, а не код

Два уникальных ограничения. Проверки в коде — это удобство для интерфейса;
настоящая защита стоит в PostgreSQL и переживает любые гонки запросов.

```sql
-- Открытым может быть только один приём: у всех открытых сеансов
-- ключ индекса одинаков, поэтому второй просто не вставится.
CREATE UNIQUE INDEX uq_session_open
    ON queue_session ((closed_at IS NULL)) WHERE closed_at IS NULL;

-- Один человек — одна запись за приём, при любом статусе.
ALTER TABLE queue_entry
    ADD CONSTRAINT uq_entry_person UNIQUE (session_id, full_name_key);
```

Группы в ключе нет намеренно: её пишет сам студент, и «поправить» её, чтобы
записаться второй раз, ничего не стоит. `full_name_key` — это ФИО, из которого
убрано всё, что человека не меняет: регистр, лишние пробелы, ё, дефис двойной
фамилии и порядок слов («Иванов Иван» и «Иван Иванов» дают один ключ).
Настоящему однофамильцу преподаватель дописывает группу к ключу — галочкой
«это однофамилец» в форме ручной записи.

Индексы и колонки, добавленные в модели после первого запуска, `create_all` в
существующую таблицу не доносит — она для него либо создаётся целиком, либо
не трогается вовсе. Поэтому при старте `_upgrade_schema()` сверяет модели с
базой и досоздаёт недостающее, пересчитав перед этим ключи ФИО. Так в рабочую
базу доехали и колонки согласия: `NOT NULL` получает `DEFAULT` из модели, и у
прежних записей он означает «согласия в базе нет».

Номер в очереди выдаётся как «максимальный + 1» под блокировкой строки приёма.
Ту же блокировку используют закрытие приёма и выход студента: запись либо
успевает до закрытия и попадает в итоговый список, либо получает отказ.
`UNIQUE (session_id, number)` остаётся дополнительной гарантией, а цикл в
`join_queue()` нужен в том числе для ручного добавления однофамильцев.
Форма привязана к конкретному приёму: отправка старой вкладки не запишет
студента в новый приём. Студент не может менять записи в закрытой истории.

Выгрузки сохраняют пользовательские поля как текст, а не формулы Excel.
Недопустимые для XLSX управляющие символы удаляются из новых комментариев
и при выгрузке старых записей.

## Персональные данные

Список людей на экране — это персональные данные, а сервис живёт в стенах
учебного заведения. Поэтому запись в очередь построена так, чтобы её не
пришлось оправдывать: у каждой строки есть согласие, у согласия — редакция и
время, у данных — срок хранения.

### Что собираем

| Данные | Зачем | Кто видит |
|---|---|---|
| Фамилия и имя | позвать именно вас, а не «следующего» | все в очереди |
| Номер группы | различить однофамильцев | все в очереди |
| Цель визита и комментарий | приём идёт быстрее | только админка |
| Номер, время, статус | порядок приёма и отчёт | номер и статус — в очереди |
| Необратимый отпечаток IP | защита от флуда, сам адрес не хранится | никто |
| Кука с токеном записи | показать свой номерок и кнопку «выйти» | только браузер |

Ни телефона, ни почты, ни номера зачётки сервис не спрашивает. Аналитики,
счётчиков и внешних CDN в нём нет: шрифты и логотип лежат рядом.

### Согласие

Студент отмечает галочку в форме записи — без неё сервер запись не примет.
Рядом короткая формулировка, полный текст — на `/privacy`, туда же ведёт
ссылка из подвала любой страницы. Кнопка «Встать в очередь» ждёт и решённое
задание, и галочку: забытое согласие не сжигает капчу.

В записи сохраняются `consent_version` и `consent_at` — редакция текста и
время. Без них согласие нельзя ни подтвердить, ни отозвать, поэтому они же
попадают в выгрузки XLSX/CSV последним столбцом и в карточку приёма в истории.
Правите формулировки в `app/templates/partials/pd.html` или на странице
`/privacy` — увеличьте `CONSENT_VERSION`: у прежних записей останется своя.

Состав данных в форме и на странице берётся из одного макроса
(`partials/pd.html`): согласие считается информированным, только если человек
согласился ровно на то, что с данными потом и происходит.

Ручная запись из админки требует галочки «согласие получено» — преподаватель
подтверждает, что спросил вслух или взял бумажное согласие; в записи это видно
как «получено лично». Тем же путём записывают студентов младше 18 лет: за них
согласие даёт законный представитель, и об этом прямо сказано на `/privacy`.

Отзыв согласия — просьба преподавателю (или письмо на `PRIVACY_CONTACT`):
запись удаляется кнопкой «Убрать». Кнопка «Выйти из очереди» — не отзыв: она
освобождает место, строка остаётся в списке приёма, и на странице про данные
это написано честно.

### Срок хранения

`RETENTION_DAYS` (по умолчанию 180) — сколько живёт закрытый приём вместе со
списком. Дальше он удаляется сам: записи уходят с ним по `ON DELETE CASCADE`.
Планировщика в сервисе нет, поэтому уборка идёт при старте контейнера и при
закрытии приёма — в панели будет видно, сколько прошлых приёмов удалено.
`RETENTION_DAYS=0` выключает уборку: сервис снова хранит историю бессрочно, и
тогда на `/privacy` так и написано.

Тот же срок показывается студентам в тексте согласия, так что менять его
следует осознанно: обещание должно совпадать с настройкой.

**Бэкапы живут по своим правилам.** Копия, снятая до истечения срока, хранит
удалённые записи, поэтому старые дампы стоит удалять вместе с историей.

### Бэкап и восстановление

Бэкап базы:

```bash
docker compose exec -T db pg_dump -U au_queue au_queue | gzip > ochered-$(date +%F).sql.gz
```

Восстановление:

```bash
gunzip -c ochered-2026-09-18.sql.gz | docker compose exec -T db psql -U au_queue au_queue
```

По правилу 3-2-1, о котором спрашивает капча: положите копию не на тот же диск.

## Обслуживание

docker compose logs -f app        # что происходит

`docker compose up -d`. Выданные сессии живут 12 часов.

### Самопроверка

Нужны Docker с Compose, `curl`, Python 3 и Node.js 18+.

```bash
./scripts/smoke.sh
```

Скрипт собирает **отдельный тестовый стек** по `scripts/compose.test.yml`:
своя сеть, PostgreSQL с данными в памяти, тестовые учётные данные и случайный
порт на `127.0.0.1`. Рабочие `.env`, контейнеры и история не используются;
переопределение `BASE` или `COMPOSE_FILE` не направляет тесты в рабочий сервис.
При завершении, ошибке или Ctrl+C тестовые контейнеры, сеть и данные удаляются.

Проверяются вход, открытие и закрытие приёма, конец записи по часам и
автозакрытие опустевшей очереди, все типы капчи (верный ответ, разбор ошибки,
сгоревшее задание и замена другого типа), выдача номеров, уникальность записей и открытого приёма на уровне БД, валидация форм,
обязательное согласие на обработку данных и страница `/privacy`, фамилия из
двух слов и отказ тому, кто дописал к ФИО слово, фильтр брани (в том числе
латиницей и по слогам), видимость имён, свой номер и положение, выход,
отметки, ручная запись, выгрузки XLSX/CSV со столбцом согласия, печать, QR,
история и поиск.

Затем запускаются регрессии из `tests/`: конкурентные запросы к PostgreSQL,
устаревшие формы, защита архивных записей, формулы и управляющие символы в
экспорте, запись редакции согласия, удаление приёмов по сроку хранения,
досоздание колонок согласия в уже существующей таблице, отказ отчеству при
живой сербской фамилии, ложные срабатывания фильтра на настоящих фамилиях, а
также клиентское автообновление, маска группы, разбор всех типов капчи,
замена задания после ошибки и кнопка записи, которая ждёт обе галочки.
Клиентские проверки выполняют настоящий `app.js` в Node.js с моделью DOM,
без npm-зависимостей.

При необходимости задать зеркала образов:

```bash
TEST_POSTGRES_IMAGE=mirror.gcr.io/library/postgres:16-alpine \
TEST_PYTHON_IMAGE=mirror.gcr.io/library/python:3.12-slim ./scripts/smoke.sh
```
